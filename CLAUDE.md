# superiorAPI

## Workflow

- Work in committed steps: split each task into small, self-contained steps and commit each one once it works, before starting the next. Don't let several changes pile up in one uncommitted diff.
- Each commit should build and pass tests on its own.
- Use the repo's commit style: `type(scope): summary`, e.g. `feat(web): ...`, `build(api): ...`, `ci: ...`.
